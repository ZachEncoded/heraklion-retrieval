# Heraklion Retrieval System

A focused **information-retrieval component** for the Municipality of Heraklion
website (`heraklion.gr`). Given a citizen query, it returns the most relevant
municipal **pages/documents** — ranked by BM25 with Greek-aware text processing
and a recency boost.

It is designed to be called by an upstream chatbot/RAG: once that system has
decided the citizen wants **information** (not an e-service), it hands the query
to this component to find the right page.

---

## What it does

- **Crawls** `heraklion.gr` politely (respects robots.txt, rate-limits,
  deduplicates), extracting each page's text, attached **PDF contents**, and
  **publish date** into one JSON document per page.
- **Indexes** the corpus into a **BM25** model (plus TF-IDF), with a light Greek
  stemmer and field weighting (titles count more than body).
- **Searches** with BM25 + a mild **recency boost**, returning ranked
  title + URL results.
- **Updates** itself: a fast daily per-section refresh, plus a monthly full crawl.

Benchmarked against the official site search across 10 real citizen queries, it
**matched or beat** the site on **9 of 10** — winning most clearly on natural,
recency-sensitive queries (and never returning zero results, which the site did).

## Repository layout

```
crawler/     crawler.py        the crawler (fetch → extract → dedup → corpus/)
             category_map.py   section → listing-page map + baseline state (library)
             daily_update.py   fast daily refresh (per-section link diff)
indexing/    build_index.py    build TF-IDF + BM25 index from the corpus
             bm25.py           BM25 ranking + recency boost (library)
             build_chunks.py   optional passage-level index
             greek_text.py     Greek tokenizer + stemmer (library, used at index AND query time)
             stopwords*.txt    Greek / English stopword lists
search/      search.py         query the index (BM25, default)
             evaluate.py       measure retrieval quality (regression tests)
scripts/     daily_update.bat  scheduled daily job
             monthly_crawl.bat scheduled monthly full crawl
eval/        eval_set.json     300 auto-generated known-item queries
             eval_crossform.json  34 hand-written cross-form queries
```

Data folders — `corpus/`, `crawl_state/`, `indexing/index/` — are **generated by
the pipeline** and git-ignored (they total ~2 GB).

## Pipeline — crawl → index → search

```
heraklion.gr ──crawler/crawler.py──▶ corpus/ + crawl_state/manifest.json
             ──indexing/build_index.py──▶ indexing/index/  (BM25, TF-IDF, doc_meta)
             ──search/search.py──▶ ranked results (title + URL)
```

### First-time / full rebuild
```bash
python crawler/crawler.py            # full crawl → corpus/
python indexing/build_index.py       # build the search index
python indexing/build_chunks.py      # (optional) passage index
python search/search.py "παιδικοι σταθμοι"
```

### Day-to-day
```bash
python crawler/daily_update.py --rebuild-index   # fetch new items + reindex (seconds)
python search/evaluate.py --scorer bm25          # measure quality after changes
```

**Rule:** whenever `corpus/` changes, re-run `build_index.py` (or use
`daily_update.py --rebuild-index`). Search reads the index, not the corpus.

## How ranking works

| Ingredient | What it does |
|---|---|
| **BM25** | Lexical ranking with tunable length normalization — beat TF-IDF cosine on every eval metric. |
| **Greek stemmer** | Collapses inflected forms (δημοτικός/ού/ό/ών → δημοτικ) so a query in one form matches docs in another. Runs at **both** index and query time. |
| **Field weighting** | Title tokens are repeated ×3 before indexing, so title matches rank higher. |
| **Recency boost** | Score × `1 + λ·0.5^(age/half-life)` using each doc's parsed publish date; nudges recent docs up among similarly-relevant ones (λ configurable in `bm25.py`). |

Semantic **embeddings were evaluated and rejected** for this corpus — they didn't
beat BM25 on the eval and added heavy dependencies. The system is intentionally
**lexical and lightweight** (numpy/scipy/scikit-learn only).

### Exclusions (hard requirements)
- **`eservices.heraklion.gr`** is never crawled or indexed — e-service intents are
  handled upstream (enforced in both `crawler.py` and `build_index.py`).
- The `/en/` mirror is excluded (broken/empty pages, crawler traps).

## Evaluation

`search/evaluate.py` scores retrieval quality against two fixed query sets, so any
change can be judged objectively (it's the project's regression test):

```bash
python search/evaluate.py                                  # exact-snippet set (300)
python search/evaluate.py --set eval/eval_crossform.json   # cross-form set (34)
```
Metrics: **Hit@1**, **MRR@10**, **Recall@5**, misses. Every tuning decision
(stemming, BM25, recency λ, dropping embeddings) was made from these numbers.

## Notes on robustness

- The crawler is **incremental** (conditional GETs, PDF text cache) and **trap-safe**
  (calendar loops, cache-buster params, relative-link accumulation are all filtered;
  a productivity/quarantine + hard ceiling guarantee it always terminates).
- **Content dedup** collapses the same article published under multiple URLs.
- A page is re-processed when its **set of attached PDFs changes**, so a PDF added
  to an existing page is picked up on the next crawl.
